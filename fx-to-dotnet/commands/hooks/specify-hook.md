You are the `after_specify` HOOK for the `fx-to-dotnet` extension. You run automatically after `speckit.specify` completes. Your job is to make the `## Migration Context` section deterministic and idempotent when .NET Framework projects are present.

`{featureDir}` is the active Spec Kit feature folder (`specs/<branch>/`). Resolve it from `SPECIFY_FEATURE` or the current git branch. If no active feature folder is detectable, **silent-exit success**.

<contract>
- This hook is **MANDATORY** (`optional: false` in `extension.yml`).
- On non-Framework workspaces: **silent-exit success** (exit 0; no edits).
- On Framework workspaces: `spec.md` MUST contain exactly one `## Migration Context` section anchored by `> **Preset-managed**`.
- The hook may fail non-zero only on true parse/write errors or missing required inputs after detection succeeds.
</contract>

<workflow>

## 1. Detect migration context

Invoke `speckit.fx-to-dotnet.detect` for the active feature and workspace.

- If detection reports no .NET Framework projects, exit 0 with no edits.
- Ensure `{featureDir}/migration/detection.md` exists (re-run detect if needed).

## 2. Load source artifacts

Read:

1. `{featureDir}/migration/detection.md` (source of truth for project count and classification)
2. `{featureDir}/spec.md`

If `spec.md` is missing, exit non-zero with a clear error.

## 3. Build deterministic section body

Generate a normalized `## Migration Context` section using detection results:

```markdown
## Migration Context

> **Preset-managed** — this section is generated by the `fx-to-dotnet` preset's specify template and enforced by the `after_specify` hook. Re-run `/speckit.specify` to refresh. Do not edit by hand.

This workspace contains .NET Framework projects that require migration to modern .NET before user-story implementation can begin.

### Detection Summary

- .NET Framework projects detected: yes
- Framework versions observed: <versions from detection.md>
- Project count detected: <count from detection.md>

### Classification (high level)

- Web projects: <count>
- Service projects: <count>
- Class library/data/domain/model projects: <count>
- Test projects: <count>

### Migration Requirement

Migration must complete before user-story implementation begins. The `before_implement` hook enforces this gate.
```

## 4. Write section idempotently

Search `spec.md` for heading `## Migration Context`.

- If present: replace the full section body from that heading to (but not including) the next `## ` heading.
- If absent: append section at end of file.

Do not modify any other section.

## 5. Validate postconditions

After write, verify:

- Exactly one `## Migration Context` heading exists.
- The section contains the `> **Preset-managed**` anchor.

On failure, exit non-zero with a clear remediation message.

## 6. Exit

Exit 0 on success.

</workflow>

<idempotency-rules>
- Always locate `## Migration Context` before appending.
- Replace body on rerun; never duplicate the heading.
- Preserve all content outside the managed section.
</idempotency-rules>

<silent-exit-rules>
- No Framework projects detected -> exit 0 with no edits.
- If `{featureDir}` cannot be resolved -> exit 0 (no-op) to avoid breaking ordinary workflows.
</silent-exit-rules>
